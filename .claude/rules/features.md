# Feature spec rules

## Do

- Start from `docs/features/_template.md`.
- Write acceptance criteria that a test or command can prove.
- List edge cases, failure behaviour and who may perform each action.
- Name the API changes before implementation starts.
- Ask the user when a requirement is ambiguous. Record the answer in the spec.

## Don't

- Don't build anything listed under "Out of scope".
- Don't add unrequested features to the plan. Propose them separately.
- Don't mark a criterion done without evidence.
